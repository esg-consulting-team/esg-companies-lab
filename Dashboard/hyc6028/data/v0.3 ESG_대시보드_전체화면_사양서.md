## 00. 구현 전제

> **구현 순서**: §13 디자인 시스템의 토큰(색·폰트·간격)을 먼저 설정한 뒤 §03부터 화면을 만든다. 모든 색과 크기는 §13의 CSS 변수를 통해서만 지정하고, 컴포넌트에 색상 리터럴을 직접 쓰지 않는다.

- **화면 7개**: L1 종합 현황 / L2 영역별 진단 / L3 항목 상세 / L4 비교 분석 / L5 개선 로드맵 / L6 증빙 데이터룸 / L7 리포트
- **공통 셸**: 상단 앱바 + 좌측 레일(178px) + 본문 + 우측 AI 상담 패널(300px, 접으면 40px 스트립)
- **데이터**: 모든 수치는 API 바인딩. 개발 단계에서는 §10 목 데이터 사용.

### 표시 원칙 4가지 (전 화면 공통, 위반 시 버그로 취급)

1. 가채점 점수에는 항상 `가채점` 표기를 붙이고 KCGS 공식등급과 시각적으로 분리한다.
2. 예상 점수 상승·비용·기간에는 `예상치` 임을 명시한다.
3. 벤치마킹 기업은 `벤치마킹 A~D` 익명 코드로만 노출한다. 실명·원문 접근 불가.
4. 모든 차트에는 Exhibit 번호와 하단 출처 한 줄을 붙인다.

## 13. 디자인 시스템

컨설팅 보고서 양식을 화면으로 옮긴 규칙. **기본은 흰 바탕 · 헤어라인 · 네이비 단색**이며, 색은 의미가 있을 때만 쓴다.

### 13.1 폰트

```html
<link rel="stylesheet"
  href="https://fonts.googleapis.com/css2?family=Noto+Serif+KR:wght@500;600;700&family=Noto+Sans+KR:wght@300;400;500;700&family=IBM+Plex+Mono:wght@400;500;600&display=swap">
```

| 역할 | 서체 | 무게 | 쓰는 곳 |
|---|---|---|---|
| **Display** | Noto Serif KR | 600–700 | 페이지 제목, 섹션명, 익시빗 액션 타이틀, KPI 수치 |
| **Body** | Noto Sans KR | 300–500 | 본문, 표 셀, 설명, 라벨. 기본 300(Light), 강조 명사만 500 |
| **Utility** | IBM Plex Mono | 400–600 | 항목코드(E-7-1), 익시빗 번호, 대문자 라벨, 정렬이 필요한 수치 |

- 본문 기본: `font-size: 14.5px / line-height: 1.7 / font-weight: 400`
- 대문자 라벨은 `letter-spacing: .1em ~ .16em`, `text-transform: uppercase`
- 숫자가 열로 정렬되는 곳은 전부 `font-variant-numeric: tabular-nums`
- 제목에는 `text-wrap: balance`

### 13.2 색상 토큰

```css
:root{
  /* 표면 */
  --paper:#FFFFFF; --shell:#F5F6F8; --shell-2:#FAFBFC;
  /* 텍스트 */
```

| 토큰 | 용도 |
|---|---|
| `--navy` | 데이터 바, 강조, 액션, 링크 |
| `--navy-3` / `--navy-5` | 보조 계열, 트랙 배경 |
| `--crit` | 감점, D-day, 즉시 과제, 0점 항목 |
| `--warn` | 가채점 배지, 미확정, 중기 과제, 색인 중 |
| `--good` | 개선, 예상 상승점, 파싱 완료 |
| `--ink` / `--rule` | 본문·섹션 룰 / 표 구분선 |

**등급 칩 색 매핑**: A·A+ → `--good`, B·B+ → `--ink-3`(테두리만), C·D → `--crit`

### 13.3 간격 · 선

| 항목 | 값 |
|---|---|
| 카드 내부 패딩 | 16px 18px 18px |
| 카드 간 간격 | 16px (본문 세로), 16px (2단 그리드 gap) |
| 본문 영역 패딩 | 20px |
| 구분선 | 1px `--rule` (표 행), 1px `--rule-mid` (카드 테두리·헤더 하단) |
| 섹션 룰 | 2px `--ink` (문서 섹션 상단) |
| 강조 좌측선 | 3px (활성 내비, 경고 밴드) / 2px (인용 블록) |

레이아웃은 flex·grid의 `gap`으로 잡고, 요소별 margin으로 간격을 만들지 않는다.

### 13.4 데이터 시각화

- **비교 계열은 네이비 명도 단계로만** — `--navy`(100) / `--navy-3`(60) / `--navy-5`(10). 무지개 팔레트 금지
- 의미색은 세 가지(적·황·녹)뿐이며 **액센트와 별개**로 취급
- 도넛 게이지: 반지름 32, 선 두께 8, `-90°` 시작, 채움 `--navy`, 트랙 `--navy-5`
- 바 차트: 트랙 `--navy-5` 또는 `--shell`, 채움 `--navy`. 벤치마킹 평균은 얇은 세로선 + 삼각 마커
- 다이버징 바: 중앙 0선 `--rule-strong`, 음수 `--crit`(좌), 양수 `--good`(우)
- 차트 텍스트는 반드시 테마 토큰에서 색을 가져온다. SVG는 viewBox에 라벨 여백을 남기고 모든 도형에 명시적 `fill` 지정

### 13.5 컴포넌트 규칙 6가지

| # | 규칙 | 내용 |
|---|---|---|
| **01** | 모서리는 각지게, 그림자는 없이 | `border-radius: 0`, `box-shadow: none`. 영역 구분은 1px 헤어라인과 여백으로만. 카드가 떠 보이면 보고서가 아니라 앱이 된다 |
| **02** | 모든 차트에 액션 타이틀 | "영역별 달성률"이 아니라 "네 영역 모두 평균에 30%p 이상 미달". 제목이 결론을 말하고 차트는 근거가 된다 |
| **03** | 익시빗 번호와 출처를 붙인다 | 각 차트에 `Exhibit N` 라벨과 하단 출처 한 줄 고정. 고객사가 그대로 내부 보고에 옮길 수 있어야 한다 |
| **04** | 데이터는 네이비 단색 계열 | 비교 계열은 명도 단계로 분리 |
| **05** | 의미색은 세 가지만 | 적=감점·기한, 황=미확정·검토, 녹=개선폭. 그 외 장식적 색 금지 |
| **06** | 표는 가로줄만 | 세로 괘선·줄무늬 제거, 헤더 하단과 합계 상단만 굵게. 숫자는 우측 정렬 + tabular-nums |
