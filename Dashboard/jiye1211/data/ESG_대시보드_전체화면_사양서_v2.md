> 대상: 컨설팅 고객사 전용 단일 기업 뷰

> 버전: v1.0 · 2026.09.18 — L1~L7 전체 실구현 반영 완료 · §13은 v0.5 라이트테마 그대로 유지

## 00. 구현 전제

> **구현 순서**: §13 디자인 시스템의 토큰(색·폰트·간격)을 먼저 설정한 뒤 §03부터 화면을 만든다. 모든 색과 크기는 §13의 CSS 변수를 통해서만 지정하고, 컴포넌트에 색상 리터럴을 직접 쓰지 않는다.

### 00.0 스택 · 실행 방법

| 구분 | 내용 |
|---|---|
| Backend | Python + FastAPI (`backend/`) — Supabase에서 읽어 화면용 JSON으로 가공. `uvicorn app.main:app --reload --port 8000` |
| Frontend | React 19 + TypeScript + Vite (`frontend/`) — §13 디자인 시스템(라이트 단일 테마 · KCGS 공식 팔레트) 그대로 구현. `npm run dev` → `http://localhost:5173` |
| 배치 파일 | `start-all.bat` — 백엔드·프론트엔드를 각각 새 cmd 창으로 띄운다(포트 8000/5173). 최초 실행 시 `backend/start-backend.bat`이 `.venv` 생성 + `requirements.txt` 설치를, `frontend/start-frontend.bat`이 `npm install`을 자동으로 처리한다. `stop-all.bat` — 8000/5173 포트를 쓰는 프로세스를 찾아 종료한다 |
| AI 상담 | Gemini `gemini-embedding-001`(임베딩) + `gemini-3.6-flash`(생성). 근거는 `backend/data/rag_index.sqlite3`(로컬 파일, Supabase 아님) — §01 F5, 아래 00.1 참고 |

- **화면 7개**: L1 종합 현황 / L2 영역별 진단 / L3 항목 상세 / L4 비교 분석 / L5 개선 로드맵 / L6 증빙 데이터룸 / L7 리포트 — **전체 실구현 완료**(레일 메뉴 전부 활성화, §14 알려진 이슈 제외).
- **공통 셸**: 상단 앱바 + 좌측 레일(178px) + 본문 + 우측 AI 상담 패널(300px, 접으면 40px 스트립)
- **데이터**: 모든 화면이 실제 API(`http://127.0.0.1:8000`)에 바인딩되어 있다. §10(목 데이터)은 개발 초기 바인딩용으로 남아 있었으나, 현재는 실제 Supabase 스키마로 완전히 대체되었다 — 아래 00.1 참고.

### 표시 원칙 4가지 (전 화면 공통, 위반 시 버그로 취급)

1. 가채점 점수에는 항상 `가채점` 표기를 붙이고 KCGS 공식등급과 시각적으로 분리한다.
2. 예상 점수 상승·비용·기간에는 `예상치` 임을 명시한다.
3. ~~벤치마킹 기업은 `벤치마킹 A~D` 익명 코드로만 노출한다. 실명·원문 접근 불가.~~ **실제 구현은 이 원칙을 따르지 않는다** — 이 콘솔은 컨설팅 고객사 내부 전용이라 벤치마킹 익명화가 불필요하다고 판단해, L4 · L7 벤치마킹 비교는 전부 회사 실명(`backend/app/benchmark_config.py`)으로 표시한다(§01 F3-02 참고). 외부 공개용 화면이 필요해지면 그때 별도 익명화 뷰가 필요하다.
4. 모든 차트에는 Exhibit 번호와 하단 출처 한 줄을 붙인다.

### F5. AI 상담 (임베딩 기반) — 보고 있는 화면을 아는 상담원

### 3.3 ② KPI 4종

가로 4분할, 셀 사이 1px 구분선. 카드 배경·그림자 없음.

| # | 라벨 | 표시 | 보조 문구 |
|---|---|---|---|
| 1 | 가채점 총점 | 도넛 게이지 + `{총점} / {만점}` | `달성률 {rate}% · 항목당 100점 정규화 기준` — **v0.5의 "▲ +23 vs 2024" 전년대비 델타는 없다**(§01 F1-04, `esg_diagnosis`가 단일 연도 스냅샷) |
| 2 | KCGS 공식등급 | 등급 칩 + `{연도}년 통합등급` | 전년 대비 등급 등락 화살표(▲/▼/—, `GradeChangeArrow`)만 표시. 등급 자체가 없으면 `미확보` 배지 — **v0.5의 "벤치마킹 A~A+ · 5단계 격차" 벤치마킹 비교 문구는 없다** |
| 3 | 근거 불충분 항목 | `{불충분 건수} / {assessment.totalItems}` | `부분 인정 {N}건 포함` |
| 4 | 개선 과제 | `{즉시+중기+장기} 건` | `즉시 {N} · 중기 {N} · 장기 {N}` |

도넛 게이지: 반지름 32, 선 두께 8, `-90°` 시작, 채움은 네이비 단색(§13.4와 동일 — `frontend/src/components/DonutGauge.tsx`).

> **⚠️ 버그 — KPI 3 "근거 불충분 항목" 분모가 회사별 적용 항목수를 반영하지 않는다.** 분모로 쓰는 `assessment.totalItems`는 `esg_diagnosis`의 전체 행 수(두 회사 모두 42)이고, 분자인 `evidenceCounts.불충분`도 업종특화 등 "해당 없음"(N/A) 항목까지 포함해 센다. 반면 실제 채점 대상(`applicable`)은 회사마다 다르다 — 예: DN오토모티브는 42개 중 36개만 채점 대상이고 나머지 6개는 업종특화상 "해당 없음"이다. 즉 KPI는 항상 "X / 42"로만 표시되고, 정확한 분모여야 할 "X / 적용항목수(applicableItems)"는 쓰이지 않는다. §14 알려진 이슈 참고.

핵심 문제 카드(있는 회사만): KPI 행 아래에 회사별 고정 문구 카드 2~3장(`keyIssues`, `backend/app/mock_data.py` — 컨설팅 보고서 원문을 요약·수정 없이 옮긴 것)이 "①②③" 형태로 나열된다. v0.5 목데이터에는 없던 요소다.

## 13. 디자인 시스템

컨설팅 보고서의 정보 구조(액션 타이틀·익시빗·출처 각주)는 유지하되, 표면 위계·코너·모션은 **Bezier Design System**(채널톡, Apache-2.0)의 구조를 참조해 라이트 전용으로 재설계한다. 색과 폰트는 Bezier의 것을 쓰지 않는다 — **KCGS 공식 리포트 팔레트(§13.2)와 시스템 한글 폰트(§13.1) 외의 값은 어떤 컴포넌트에도 리터럴로 넣지 않는다.**

### 13.0 차용 범위 (Bezier에서 가져오는 것 / 가져오지 않는 것)

| 구분 | 가져온다 | 가져오지 않는다 |
|---|---|---|
| 색 | 표면-텍스트를 alpha(불투명도) 위계로 쌓는 방식 | blue/purple/pink/cobalt 등 Bezier 고유 무지개 액센트 |
| 형태 | 8~12px 라운드 + 모달 20px, elevation 표면 단계 | squircle 전용 컴포넌트(`SmoothCornersBox`) — 웹 표준 CSS로는 근사만 가능하므로 단순 `border-radius`로 대체 |
| 타이포 | 2-weight(400/700) 이원화 철학 | Inter + Noto Sans KR 조합 — 대신 §13.1의 한글 시스템 폰트 사용 |
| 간격·모션 | 4px 그리드(4/6/10/16/32), 150ms `cubic-bezier(0.3,0,0,1)` | breakpoint 토큰(Bezier는 미발행 — 본 사양서 §11 반응형 규칙을 그대로 따름) |
| 테마 | 시맨틱 토큰이 테마를 분기하는 구조 자체 | 다크 테마 — 본 프로덕트는 **라이트 단일 테마**(요구사항: 배경 흰색 · 글자 검정)로 고정하고 다크 분기를 두지 않는다 |

### 13.1 폰트

웹폰트 CDN을 쓰지 않는다. 아래 시스템 폰트 스택만 사용한다(OS별로 자동 폴백).

```css
--font-family: 'Malgun Gothic', 'NanumGothic', 'AppleGothic', 'Noto Sans CJK KR',
               -apple-system, BlinkMacSystemFont, sans-serif;
```

Bezier의 2-weight(400/700) 이원화를 그대로 따른다 — 시스템 한글 폰트는 중간 굵기(500·600)의 렌더링 품질이 OS마다 달라, **Regular(400)과 Bold(700) 두 단계만** 쓴다.

| 역할 | 크기 / 굵기 | 쓰는 곳 |
|---|---|---|
| 액션 타이틀 | 18px / 700 | 익시빗 결론 문장, 페이지 제목 (대비 확대, 기존 15px) |
| 부제 | 12.5px / 400, `--ink-2` | 익시빗 부제, 설명 |
| 본문 | 14px / 400 | 표 셀, 라벨, 상담 답변 |
| KPI 수치 | 32px / 700 | KPI 카드 대형 숫자 (대비 확대, 기존 28px) |
| 유틸리티 라벨 | 11px / 700, `letter-spacing:.08em`, uppercase | 익시빗 번호, 상태 배지 |

- 숫자 정렬 열은 `font-variant-numeric: tabular-nums` (시스템 폰트에서도 대부분 지원)
- 항목코드(`E-7-1` 등)처럼 모노스페이스가 없어 정렬이 흔들리는 값은 `white-space: nowrap` + `letter-spacing: .02em`으로 근사한다 — 기존 IBM Plex Mono만큼의 폭 정합은 포기한다
- 제목에는 `text-wrap: balance`

### 13.2 색상 토큰 — KCGS 팔레트 전용

등급·의미색·네이비·비교·변화·단계·흐름 계열 전부가 사용자가 제공한 팔레트(그림 2.5-1~2.5-7)에서 그대로 온 것이다. 새 색상을 추가로 정의하지 않는다. 표면·텍스트·선 3종만 라이트 테마에 맞춰 재정의한다(데이터 색상은 흰 바탕 위에서 원래 설계된 값이라 그대로 유지).

```css
:root{
  /* 표면 — 흰색 기반 계단식 (Bezier의 표면 위계 구조 차용, 검정 계단식을 반전) */
  --paper:#FFFFFF;      /* 최상위 배경 */
  --shell:#F5F6F8;      /* 앱바 · 레일 */
  --shell-2:#FAFBFC;    /* 카드 · 패널 (elevation 1) */
  --shell-3:#F0F1F4;    /* 모달 · 드롭다운 · 상담 인용 카드 (elevation 2) */

  /* 텍스트 — 블랙 알파 위계 (Bezier의 black-85/60/40 그대로) */
  --ink:rgba(10,10,10,.92);         /* 본문 기본 */
  --ink-2:rgba(10,10,10,.68);       /* 보조 텍스트 · 부제 */
  --ink-3:rgba(10,10,10,.44);       /* 3차 텍스트 · 캡션 · 출처 각주 */
  --ink-on-light:#1F1F1F;           /* TEXT_DARK — 밝은 색 배지(B+/B) 위에서만 사용, §13.2.1 */
  --ink-on-dark:#FFFFFF;            /* 어두운 색 배지·칩·필(A+/A/C/D, 네이비 필 등) 위에서만 사용, §13.2.1 */

  /* 선 */
  --rule:rgba(10,10,10,.08);
  --rule-mid:rgba(10,10,10,.14);
  --rule-strong:rgba(10,10,10,.28);

  /* 네이비 계열 — FLOW_SHADES·HEATMAP_HIGH 재사용 (그림 2.5-6·2.5-7), 데이터 강조 전용 */
  --navy:#203864;      /* = HEATMAP_HIGH = FLOW_SHADES[6] */
  --navy-2:#3F6FA5;    /* = FLOW_SHADES[5] */
  --navy-3:#6C9BD2;    /* = FLOW_SHADES[4] */
  --navy-4:#9BB7D8;    /* = FLOW_SHADES[3] */
  --navy-5:#EAF1F8;    /* = HEATMAP_LOW */

  /* 의미색 3종 — CHANGE_COLORS 재사용 */
  --crit:#C00000;              /* 하락 · 감점 · D-day · 즉시 · 0점 */
  --crit-bg:rgba(192,0,0,.12);
  --warn:#8A6412;              /* 가채점 · 미확정 · 중기 · 색인 중 (= GRADE B+ 원색을 흰 배경 텍스트용으로 어둡게) */
  --warn-bg:rgba(255,192,0,.16);
  --good:#548235;              /* 개선 · 상승폭 · 파싱 완료 (= COLOR_MAIN = CHANGE 개선) */
  --good-bg:rgba(84,130,53,.12);

  /* 등급 칩 — KCGS 공식 6단계 (그림 2.5-1) */
  --grade-a-plus:#375623;
  --grade-a:#548235;
  --grade-b-plus:#FFC000;
  --grade-b:#ED7D31;
  --grade-c:#C00000;
  --grade-d:#7F0000;

  /* 두 집단 비교 — 우수/발행군 vs 미흡/미발행군 (그림 2.5-2·2.5-5) */
  --group-main:#548235;
  --group-sub:#A6A6A6;

  /* 변화 방향 (그림 2.5-3) */
  --change-up:#548235;
  --change-flat:#A6A6A6;
  --change-down:#C00000;

  /* 3단계 진행 판정 — 보고서 발행 유형(그림 2.5-4)을 파싱 상태 등에 재사용 */
  --stage-1:#548235;   /* 완료 · 둘 다 발행 */
  --stage-2:#A9D18E;   /* 진행 중 · 하나만 발행 */
  --stage-3:#A6A6A6;   /* 미제출 · 모두 미발행 */

  /* 흐름도 7단계 (그림 2.5-7) */
  --flow-1:#DCE6F2; --flow-2:#C9D8EA; --flow-3:#B2C8E1; --flow-4:#9BB7D8;
  --flow-5:#6C9BD2; --flow-6:#3F6FA5; --flow-7:#203864;
  --flow-arrow:#7F7F7F;
  --flow-note:#C00000;   /* 예외 주석 (예: "주총 종속") */

  /* 차트 보조축 */
  --axis:#7F7F7F;
  --grid:#EBEBEB;
}
```

다크 테마 분기는 두지 않는다. `prefers-color-scheme`이나 `data-theme` 분기 없이 위 값을 그대로 전역 기본값으로 쓴다. `--warn`은 원본 팔레트의 `#FFC000`(GRADE B+)이 흰 배경 위 텍스트로는 대비가 부족해(1.6:1) `#8A6412`로 어둡게 조정했다 — `--warn-bg` 틴트와 등급 칩(`--grade-b-plus`)의 원색은 그대로 유지한다.

#### 13.2.1 배지·칩 위 텍스트 색상 규칙 (필수)

같은 팔레트라도 배경이 **원색으로 꽉 찬 경우**와 **옅은 틴트(`-bg` 토큰)인 경우**의 텍스트 색이 다르며, 원색이라도 명도에 따라 다시 갈린다.

| 배경 | 배경 채도 | 텍스트 |
|---|---|---|
| `--grade-b-plus`(#FFC000), `--grade-b`(#ED7D31) 칩처럼 원색이 꽉 찬 밝은 배경 | 밝음 | `--ink-on-light`(#1F1F1F) |
| `--grade-a-plus` `--grade-a` `--grade-c` `--grade-d` 칩, `--navy` 필(버튼·활성 칩) 처럼 원색이지만 어두운 배경 | 어두움 | `--ink-on-dark`(#FFFFFF) — 페이지 기본 텍스트 `--ink`를 쓰지 않는다, 라이트 테마에서는 `--ink`가 어둡기 때문 |
| `--warn-bg` `--crit-bg` `--good-bg` 같은 12~16% 틴트 배지 (배경이 사실상 흰색에 가까움) | 밝음 | 각 의미색 자체(`--warn`/`--crit`/`--good`) |

임의로 판단하지 말고 이 표만 따른다 — 대비를 매번 계산하지 않기 위한 고정 규칙이다. `--ink-on-light`/`--ink-on-dark`는 페이지 테마와 무관하게 고정된 값이므로, 어두운 색 필 위에는 항상 `--ink-on-dark`를 쓰고 절대 페이지 기본 텍스트 토큰(`--ink`)을 대신 쓰지 않는다.

### 13.3 표면 위계 · 코너 · 모션 (Bezier 구조 차용)

흰 배경에서는 `box-shadow` 없이도 표면 밝기 차이만으로 위계가 충분히 드러나므로, Bezier의 elevation(그림자 단계) 대신 **표면 밝기 단계 + 1px 알파 보더**로 위계를 표현한다. 검정 계단식과 반대로, 페이지(0단계)가 가장 밝고 위 단계로 갈수록 살짝씩 어두워진다.

| 단계 | 배경 | 보더 | 쓰는 곳 |
|---|---|---|---|
| 0 | `--paper` | 없음 | 페이지 배경 |
| 1 | `--shell-2` | `--rule` | 익시빗 카드, KPI 카드 |
| 2 | `--shell-3` | `--rule-mid` | 상담 인용 카드, 드롭다운, 툴팁 |
| 3(모달) | `--shell-3` | `--rule-strong` + 반경 20px | 모달, 다이얼로그 |

| 항목 | 값 |
|---|---|
| 버튼 · 인풋 반경 | 8px |
| 카드 · 배지 · 배너 반경 | 12px |
| 모달 반경 | 20px |
| 등급 칩 반경 | 6px (표 안에서 과도하게 둥글면 가독성이 떨어짐) |
| 간격 그리드 | 4 · 6 · 10 · 16 · 32px |
| 모션 | 150ms `cubic-bezier(0.3,0,0,1)` (호버 · 토글 · 패널 접힘/펼침) |
| 비활성 | `opacity: .4` |

레이아웃은 flex·grid의 `gap`으로 잡고, 요소별 margin으로 간격을 만들지 않는다.
