# AI 상담 챗봇 작업 요약

L1~L7 대시보드와 별개로 진행 중인 "AI 상담" 패널(우측 사이드 패널) 작업 현황 정리입니다.
대시보드 화면 작업과 최대한 충돌 없이 병행할 수 있도록 파일을 분리해 두었습니다.

## 1. 무엇을 하는 기능인가

우측 AI 상담 패널에서 회사 담당자가 질문하면, Gemini가 아래 두 가지 근거를 스스로 판단해서
조회한 뒤 답변을 종합해 줍니다.

- **문서 근거**: ChromaDB에서 마이그레이션한 ESG 보고서 원문 조각(RAG 검색)
- **정형 데이터 근거**: Supabase의 진단 점수/로드맵/벤치마킹 등 구조화된 테이블 (Gemini function calling)

근거를 찾지 못하면 웹검색으로 때우지 않고, "이런 문서를 준비해 달라"는 안내만 하도록 되어 있습니다.

## 2. 아키텍처 / 파일 구조

팀원 작업(공용 대시보드 파일)과 겹치지 않도록 챗봇 전용 코드를 별도 파일로 분리했습니다.

**백엔드 (`backend/`)**
| 파일 | 역할 |
|---|---|
| `app/chat_routes.py` | `/api/chat`, `/api/rag/status` 라우터 (공용 `main.py`에서 분리) |
| `app/rag.py` | 라우팅(어떤 함수를 호출할지) + 근거 종합 + 답변 합성의 중심 로직 |
| `app/supabase_lookup.py` | Supabase 정형 데이터 조회 함수 모음 (LLM 호출 없는 순수 조회) |
| `schema_config.py` | Supabase 테이블/컬럼명 매핑 (코드에 테이블명 하드코딩 금지, 전부 이걸 통해 간접 참조) |
| `app/gemini_client.py` | Gemini REST 호출 래퍼 (임베딩 / JSON 생성 / function calling) |
| `scripts/build_rag_index.py` | 원본 ChromaDB → `data/rag_index.sqlite3` RAG 인덱스 빌드 스크립트 |

**프론트엔드 (`frontend/src/`)**
| 파일 | 역할 |
|---|---|
| `chat/types.ts` | 챗봇 전용 타입 (`ChatCitation`, `ChatResponse`) — 공용 `types.ts`에서 분리 |
| `chat/api.ts` | 챗봇 API 호출 함수 (`chatApi.ask`) — 공용 `api/client.ts`에서 분리 |
| `chat/consult.css` | 상담 패널 전용 스타일 — 공용 `styles/layout.css`에서 분리 |
| `components/ConsultPanel.tsx` | 상담 패널 UI (위 세 파일을 가져다 씀) |

공용 파일(`main.py`, `types.ts`, `api/client.ts`, `styles/layout.css`)에는 라우터 등록/타입 재수출 같은
최소한의 연결 코드만 남겨서, 팀원이 대시보드 화면을 작업할 때 겹칠 부분을 최소화했습니다.

## 3. 지금까지 처리한 주요 이슈

1. **웹검색 제거** — 근거 부족 시 웹검색 폴백 없이 "필요 증빙 안내" 문구만 반환.
2. **Supabase function calling 추가** — 문서 검색(RAG)과 정형 데이터 조회를 Gemini가 질문에 맞게
   스스로 선택하도록 구현 (`get_company_summary`, `get_item_detail`, `get_items_by_urgency`,
   `get_roadmap_urgency_distribution`, `get_report_insight`, `get_benchmark_peer_names`,
   `search_documents` 등).
3. **벤치마킹 회사명 불일치 버그** — L4 화면에는 정상 노출되는 벤치마크 3사가 챗봇에서는
   "확인 안 됨"으로 나오던 문제. `get_benchmark_peer_names`가 대시보드와 동일한
   `repository.fetch_domain_benchmark` 로직을 재사용하도록 수정해서 해결.
4. **라우팅/종합 로직 정합성**
   - 정형 데이터가 일부만 답을 찾아도 문서 검색을 생략하지 않고 항상 병행 실행 후 병합.
   - 질문에 여러 하위 주제가 섞여 있으면 여러 함수를 동시에(병렬) 호출.
   - 최종 답변에서 "정형 데이터 근거"와 "문서 근거"를 구분 표시하고, 진짜 못 찾은 부분만
     "근거 부족"으로 표시 (전체를 근거 부족으로 뭉뚱그리지 않음).
5. **근거 카드(citation) 정리** — 깨진 표 마크업(`|---|`, 빈 셀 행 등)이 그대로 노출되던 문제를
   해결. 표에서 의미 있는 문장/숫자만 1~2줄로 추출하거나, 추출이 안 되면
   "출처: [문서명] p.[페이지] (표 데이터)"만 표시.
6. **벤치마킹 질문 시 문서 검색 범위 확장** — 비교/벤치마킹류 질문이면 현재 회사뿐 아니라
   벤치마크 피어사 문서도 함께 검색 (일반 질문은 기존처럼 현재 회사만).
7. **대화 히스토리 기반 지시어 해석** — "그거", "그 26개" 같은 후속 질문이 이전 답변을 못 알아듣던
   버그 수정. 라우팅 단계에도 최근 대화 내역을 함께 넘기도록 변경.
8. **응답 범위 분기 (`get_items_by_urgency`)** — "몇 개야"류 질문은 개수+대표 요약, "다 뭐야"/
   "목록"류 질문은 전체 항목(코드+이름)을 줄바꿈으로 전부 나열하도록 `scope: summary|full` 분기 추가.
9. **AI 상담 패널 레이아웃 고정** — 메시지가 쌓여도 페이지 전체가 늘어나지 않도록 패널을
   뷰포트 높이에 고정하고, 메시지 목록만 스크롤되게 수정 (카톡 스타일). 새 메시지 도착 시 자동
   스크롤.

## 4. RAG 인덱스 현황 (`backend/data/rag_index.sqlite3`)

`scripts/build_rag_index.py`로 원본 ChromaDB 문서를 Gemini 임베딩 API로 재임베딩해서 구축.
현재 상태:

| 회사 | 청크 수 |
|---|---|
| DN오토모티브 | 3,935 |
| 하나마이크론 | 3,820 |
| SK하이닉스 | 7,746 (완료) |
| 대한전선 | 5,573 (완료) |
| 삼성전자 | 8,844 (완료) |
| 삼성전기 | 7,590 (완료) |
| 엘에스일렉트릭 | 6,970 (완료) |
| HD현대일렉트릭 | 237 / 7,152 (**부분적, 약 3%**) |
| SK아이이테크놀로지 | 0 / 5,344 (**미완료**) |

- 벤치마킹 대상 7개사 임베딩 도중 비용 문제로 중단(`여기서 끝내자`). 하나마이크론 테스트 영상
  촬영에는 지장 없음 (하나마이크론 자체 + 이미 채워진 벤치마크사 데이터로 검색 가능).
- **HD현대일렉트릭은 데이터가 3%만 있어서, 챗봇이 "문서에 없음"이라고 잘못 확신하는 답을 줄 수
  있음** — 이어서 채우거나, 그 전까지는 이 회사 관련 질문에 주의가 필요함 (아직 미결정 사항).
- 임베딩 API(`gemini-embedding-001`)는 유료(입력 토큰당 $0.15/100만 토큰)라서, 이후 추가로
  재임베딩이 필요하면 반드시 사전에 비용 확인 후 진행 예정.

## 5. 조사했지만 보류된 것

- **원본 ChromaDB 벡터 재사용 시도**: 마이그레이션 과정에서 벡터가 유실됐다는 가설을 검증했으나,
  실제로는 원본 인덱스가 정상 작동함을 확인(자기 자신 검색 시 거리 0.0). 다만 chromadb
  라이브러리로 재사용을 시도할 때 `Error loading hnsw index` 오류가 간헐적으로 발생해 안정화에
  실패, 결국 API 재임베딩 방식으로 되돌림.
- **hnswlib 직접 로드로 우회 시도**: 이 프로젝트 환경에 MSVC 빌드 도구가 없어 `chroma-hnswlib`를
  소스 빌드할 수 없었음. Visual Studio Build Tools의 "C++를 사용한 데스크톱 데스크톱 개발"
  워크로드 오프라인 설치 캐시(1.22GB)는 `C:\vsbt_layout_probe`에 받아둔 상태이나, 관리자 권한
  터미널에서 실제 설치는 아직 진행하지 않음. (지금 당장 급하지 않아 보류 중)
